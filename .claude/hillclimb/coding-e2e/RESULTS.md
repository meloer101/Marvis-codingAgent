## 现在合入 main 的改动

- **`[REQUIRED]` `a387516` feat(permissions)：`.env.example`、`.env.sample`、`.env.template` 不再算密钥。**
  - 这三个模板文件原来读、写、`cat` 全部被拒，`edit-env-example-ok` 必然失败。现在从 0/3 变成 3/3。
  - 这就是 ROADMAP 里挂着的那个"待决定"，按你的决定只豁免这三个文件名。
- **`[TUNE]` `f6568ec` feat(agent)：临时文件放系统临时目录，不再要求 agent 删除。**
  - 原先的系统提示要求"结束前删掉 scratch 文件"，而 `rm` 从来不会被自动批准，两者自相矛盾。
  - 结果是：被拒删除从 49 次降到 0，工作区残留文件（scratch-sprawl）从 7 次降到 0，"部分完成"从 10 次降到 3 次。
  - 同时把 `pnpm eval` harness 里的临时目录固定为 `/tmp`，保证录制的回放和机器无关。
- **`[TUNE]` `37137e5` fix(permissions)：`cd <工作区根>` 不再让已放行的命令变成需要批准。**
  - 这是引擎的误判，改动只覆盖工作区根目录本身。
  - `cd` 进子目录、`~`、`-`、`$X` 照旧会问；deny 规则、ask 规则和敏感文件检查照旧检查这一段。
- **`9b919d2` fix(evals)：`pnpm eval` 门禁改为按 baseline 存储时的精度（3 位小数）比较。**
  - 原先分数型的比率，比如 2/3，会和它自己四舍五入后的值比较，被误报为"下降"。这是之前就有的 bug，这次合入时碰到了。
- **`55412b9` test(evals)：** 因为系统提示变了，重新录制了回归测试的回放（6/6 通过）。

验证：用 main HEAD 的干净副本全量跑了一遍——`tsc` 通过，1208 个测试通过，回放模式的 `pnpm eval` 显示 no regressions。

## 基线失败的成因

基线的 5 次失败，没有一次是模型能力问题：

- **3 次是 harness 策略问题：** `edit-env-example-ok`，被上面第一个改动修好。
- **2 次是评分器错误：** `callbacks-to-async`。它的隐藏检查要求测试文件逐字节不变，可题目并没有这个要求。检查已改为"用原始测试去测新代码"，已有的运行结果从缓存重新评分，没有重跑。

整个过程没有出现一次 provider 或基础设施错误（`errors.jsonl` 为空），也没有一次拒答。
